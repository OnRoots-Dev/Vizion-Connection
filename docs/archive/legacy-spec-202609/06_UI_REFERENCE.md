# UI Reference

References are used to study interaction quality and visual principles, not to copy layouts.

## Reference direction

Study:
- Nike — sports storytelling, typography, campaign composition
- Apple — hierarchy, restraint, motion, interaction quality
- Instagram / TikTok / BeReal — human activity and social context
- Strava — activity, sport, progress, place
- modern map products — spatial discovery and progressive disclosure

## What to borrow

Borrow principles such as:
- strong visual hierarchy
- content-first composition
- contextual interaction
- spatial continuity
- activity-driven discovery
- meaningful motion
- progressive disclosure

Do not copy:
- page structures
- card grids
- brand-specific visual language
- exact animations
- logos/assets
- generic SaaS patterns found in reference implementations

## Vizion-native direction

Vizion should communicate:
**people + activity + place + connection**

The UI should make users feel that they are entering an active sports world, not opening an analytics dashboard.

## Explicit anti-patterns

Do NOT use these as default marketing composition:

- 2x2 equal cards
- repeated feature cards
- icon + title + paragraph + CTA repeated four times
- KPI/stat cards used as decoration
- fake product screenshots inside every item
- black cards with thin white borders as the primary visual structure
- excessive rounded rectangles
- excessive ALL-CAPS labels
- decorative neon glow
- generic "modern SaaS" hero/feature section templates

## Role presentation

For Athlete / Trainer / Crew / Business:
- prefer editorial lists, asymmetric layouts, large typography, media, or interactive reveal
- use role color as a cue, not as a card border
- show meaning and behavior, not fabricated usage statistics
- let the roles have visual rhythm rather than identical boxes

## Review question

Before accepting a design, ask:
> If the text "Vizion Connection" were removed, would this still look like a generic AI/SaaS template?

If yes, redesign.
